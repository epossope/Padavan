# Noema Mini App — локальная версия

Интерфейс расположен в `miniapp/`, API — `miniapp_api.py`. Используется существующий сервер быстрых действий, та же база и функции бота. Новые зависимости не нужны.

## Подключение после проверки

1. Разместить обновлённый проект на сервере (в этой задаче не выполнялось).
2. Указать публичный HTTPS-адрес существующего сервера в `QUICK_ACTIONS_BASE_URL`.
3. Mini App доступен по этому адресу с окончанием `/app`. Кнопка открытия появляется в разделе «Ещё» бота.
4. В @BotFather: `/mybots` → выбрать бота → Bot Settings → Configure Mini App → Enable Mini App. Указать полный HTTPS-адрес с `/app`. Это добавит открытие приложения из профиля бота. Названия пунктов могут немного различаться в клиенте.
5. Для кнопки около поля ввода: отправить @BotFather `/setmenubutton`, выбрать бота, указать тот же адрес и название «Открыть Noema». Существующая кнопка «Открыть Noema» в разделе «Ещё» также остаётся.
6. В оформлении Mini App в BotFather установить логотип, фон `#0A0A0A`, добавить скриншоты. Обычный localhost-адрес с ПК для пользователей Telegram не работает: нужен доступный извне HTTPS.
7. Проверить на тестовом пользователе задачи, напоминания, часовой пояс, брифинг, голос и доступ к микрофону на iOS/Android. Проверить два разных аккаунта: данные и раскладка не должны смешиваться.

Не нужен новый бот или новые пользовательские API-ключи. Публикуется обновлённый существующий сервис вместе с `miniapp/` и `miniapp_api.py`; только статические файлы без API не обеспечат работу. Базу и секреты сохранять на сервере, не помещать в публичную папку. Не менять рабочий URL быстрых команд без необходимости.

Официальная инструкция Telegram: https://core.telegram.org/bots/webapps#launching-mini-apps-from-the-menu-button

Открытие обычной ссылкой без подписанного Telegram initData — только просмотр оформления, без доступа к пользовательским данным. Ключи API не передаются браузеру.

## Реализовано

Сегодня, задачи, напоминания, заметки/файлы, люди, бюджет, правила, настройки брифинга и текстовый/голосовой запрос к существующему ассистенту. История диалога общая с ботом. Транскрипция отдельно в Telegram не отправляется. Режим голосового ответа относится к боту; Mini App пока показывает ответ текстом.

Первый брифинг нового пользователя запланирован через 150 секунд после /start (проверка каждые 30 секунд), далее 08:30 местного времени. Существующие настройки не сбрасываются. При неизвестном часовом поясе используется текущий стандартный пояс бота — пользователь может поменять его в настройках. Задержки сети могут увеличить время доставки.

## Границы первой версии

Это не завершённый перенос всех функций бота: административные ключи, iPhone и палитра эмодзи остаются в Telegram. Архив показывает последние 50 заметок и 100 файлов; отдельный поиск обращается к существующей памяти backend. Задачи и напоминания — до 200 записей, люди — текущая выборка backend. Бюджет считает полный выбранный период отдельно по валютам, отображает первые 100 операций. Загрузка/скачивание файлов через интерфейс и полная пагинация ещё не реализованы. Файлы пока присылаются в чат бота.

Питание, подписки, банковские счета, отдельные встречи с локациями, закрепление/категории заметок и недельные отчёты из ТЗ требуют расширения backend. «Ближайшее» сейчас показывает настоящее напоминание, а не вымышленную встречу. Категории задач не добавлены, поскольку в текущей модели их нет. Полного 1:1 функционального соответствия ТЗ пока нет.

## Адаптация по двум документам EAGENT

- Монохромная палитра, локальные IBM Plex Sans/Mono, тонкие SVG-иконки и общие карточки/контролы.
- Нет нижней панели вкладок; снизу фокус, сфера и клавиатура. В настройках сфера отсутствует.
- Домашние виджеты: удержание 420 мс позволяет перетаскивать карточку прямо на главном экране. Короткое нажатие открывает раздел, обычный свайп до удержания прокручивает экран. Замена/скрытие/восстановление остались в настройках. Раскладка сохраняется для подписанного пользователя на сервере; в обычном предпросмотре — только в памяти вкладки.
- Календарь и погода в едином модуле. Погода запрашивается через существующий backend с кэшем 5 минут.
- Три раздела задач, раскрытие деталей, поиск людей, поиск по памяти, периоды бюджета.
- Сфера Canvas: нейтральная полупрозрачная оболочка, состояния и реакция на уровень микрофона, reduced-motion. Процедурная интерпретация референса, не его покадровая копия. Удержание для push-to-talk ещё не реализовано; запись запускается/останавливается нажатием.

Упомянутый в ТЗ `EAGENT_DESIGN_TOKENS.json` не приложен и не найден в корне NoemaDiz. Здесь создан одноимённый файл по палитре и требованиям двух переданных документов. `tokens.js` загружает его для всех экранов. NoemaDiz не изменялся. Код без дополнительной сборки: `ui.js` — общие компоненты, `app.js` — API/формы, `screens.js` — композиция экранов, `orb.js` — мембрана.

Локальная проверка: `python -m unittest discover -s tests -t .`; браузерная проверка `node tests/miniapp_visual.cjs` (требуется Playwright и локальный сервер на 8091; путь к Playwright можно задать через PLAYWRIGHT_PATH). Проверяются 8 экранов при 6 размерах viewport и настройка виджетов. Это не проверка настоящей Telegram-сессии или успешной работы внешних провайдеров.

Сфера — процедурная анимированная полупрозрачная мембрана Canvas, без видеофайла. Видео/GIF можно показать внутри страницы после её загрузки; заменить ими собственный экран загрузки Telegram нельзя через Mini App API.

Перед публичным использованием нужна проверка на настоящем Telegram-клиенте. Локальные тесты не проверяют доставку Telegram, доступность новостного провайдера или работу микрофона на конкретном устройстве.

## Мобильные правки по комментариям

Убраны дополнительные ссылки под карточками, кнопка настройки виджетов и колокольчик в заголовке. Сфера увеличена и закреплена внизу рабочих экранов. В чате история прокручивается отдельно, сфера и поле ввода находятся внизу; visualViewport учитывает экранную клавиатуру. Периоды бюджета оформлены компактными текстовыми вкладками. `mobile.css` и `mobile.js` содержат эти правила и прямое touch-перетаскивание.

Нажатие на сферу больше не открывает чат. Обычный push-to-talk endpoint сохранён. Режим «Разговор» лениво загружает локальный Vosk wake word, держит двухсекундный PCM ring buffer, использует Voxtral Realtime как основной STT и автоматически возвращается к прежнему batch STT при ошибке. Ответ идёт через общий LLM stream, предложения сразу поступают в клиентский TTS; речь пользователя отменяет текущий stream и TTS. Для realtime на сервере нужен `MISTRAL_API_KEY` в `.env`/Amvera Secrets — браузер получает только короткоживущий `rt_*` token.

Telegram-текст также использует `sendMessageDraft`: обновления ограничены по символам и времени, Stop отменяет активный OpenRouter response, а готовый ответ сохраняется обычным форматированным сообщением. `python-telegram-bot` 22.8 хранит новое событие Stop в `Update.api_kwargs`, поэтому отдельное обновление dependency stack не требуется.

## Повторная сверка V2

Холст сферы в нижней панели сохраняется между обновлениями и переходами; холсты чата/календаря переиспользуются. Настройки скрывают панель, не уничтожая её. Фаза анимации не скачет при смене состояния. Перетаскиваемая карточка теперь следует за указателем отдельным слоем, соседние элементы смещаются анимацией FLIP, отпускание сопровождается мягкой посадкой. Обычный клик после перетаскивания вне сетки не блокируется.

`refinement.css` уточняет контуры стекла, типографику, активные состояния вкладок и переключатели. Добавлены отдельные расходы/доходы и диаграмма категорий по реальным данным бюджета (RUB). Полное пиксельное совпадение всех экранов не подтверждено; отсутствующие возможности backend не заменяются данными с референсов. Последняя браузерная проверка включает сохранение идентичности canvas при повторном render, 6 размеров экрана и mouse/touch drag.
