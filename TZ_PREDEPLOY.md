# ТЗ: подготовка Noema к Amvera

## Цель

Развернуть Telegram-бота Noema в Amvera без потери SQLite-памяти и вложений,
не меняя работающий ingestion/retrieval. Интерфейс должен быть компактным,
а все прежние возможности — доступны через подменю или естественные команды.

## Готовый объём

- `/data` — единственное постоянное хранилище базы и файлов; переменные и
  секреты берутся из окружения.
- `⚙️ Настройки → 🧠 Модель` показывает текущую основную модель и список
  разрешённых. Выбор хранится по `chat_id` в `user_settings` и применяется
  через `ModelRouter.resolve(chat_id, task_type)` к следующему запросу.
- `TelegramRenderer` экранирует динамический текст, переводит Markdown в
  Telegram HTML и делит длинные ответы около 3700 символов по абзацам/фразам.
- При `finish_reason=length` пишется диагностическая запись в логи.
- Главная клавиатура: «Знания», «Сегодня», «Создать», «Поиск», «Настройки»,
  «Ещё». Второстепенные действия находятся в inline-подменю.
- Память остаётся универсальной: `knowledge_items` дополняются `entities`,
  `knowledge_entities`, `entity_relations`, `facets`, `knowledge_facets`.
  Типы и отношения — расширяемые строки, а relation всегда содержит источник
  `knowledge_item_id` и confidence.
- Внешние URL — часть одного knowledge item, а не самостоятельная «база
  ссылок». В UI не показываются hashes, confidence, entity dump или metadata.

## Приёмка

1. После выбора новой модели следующее сообщение отвечает ею без рестарта.
2. `**Проект:** Noema` отображается без звёздочек и с жирным заголовком.
3. Длинный ответ доставляется полностью несколькими сообщениями.
4. Даты, время, суммы, расширения и UI-ярлыки не становятся людьми.
5. Один объект может быть связан с несколькими другими через одну исходную
   запись, без дублирования knowledge item.
6. Старые тесты и новые тесты проходят до деплоя.
